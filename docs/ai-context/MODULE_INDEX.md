# Module Index

Only architecturally important modules are indexed here. Use Atlas/Serena for lower-level navigation.

| Module | Responsibility / important interfaces | Depends on | Main consumers | Constraints | Paths |
| --- | --- | --- | --- | --- | --- |
| Server Actions | Guarded application mutations; public exports in `app/actions.ts`; gates from `_shared.ts` | auth facade, domain services and composition modules | web UI/client components | Preserve public names/signatures and `{ error }` shape; gate every action | `app/actions.ts`, `app/actions/` |
| Web HTTP boundary | Same-origin auth/data API; `originCheck`, `requireSignedIn`, `requireActive` | auth facade, domain services | browser data/auth clients | Cookie mutations remain origin-protected | `app/api/_http.ts`, `app/api/auth/`, `app/api/data/` |
| Mobile HTTP boundary | Versioned REST; `requireMobileActor`, `withMobileActor`, response helpers | mobile token/session state, services/domain | React Native `ApiClient` | Bearer-only by default; coordinate DTO changes with mobile | `app/api/v1/` |
| Auth facade | Backend-neutral server identity; native/Supabase implementations | backend selector, cookies/Supabase, profile state | actions, route guards, services | Session validity does not imply authorization | `lib/auth/index.ts`, `lib/auth/` |
| Browser auth/data | Client-safe auth plus backend-neutral HTTP/data access | auth facade, versioned/compatibility HTTP endpoints | web UI | Must not import server-only DB/auth modules; browser timesheet reads use `/api/v1` | `lib/auth/client.ts`, `lib/data/client.ts`, `lib/backend/` |
| Shared core | Platform-neutral date arithmetic, calculations, and validation | no app/server/mobile runtime | contracts, web, mobile | Must remain platform-neutral | `packages/core/` |
| Shared contracts | Canonical request schemas, input types, response DTOs | `@vsis/core`, Zod | v1 services, browser client, mobile client | Wire fields must stay compatible across server/web/mobile | `packages/contracts/` |
| Shared client | Typed HTTP operations and platform-neutral client logic | `@vsis/contracts` | browser and mobile clients | Keep platform-neutral; no Next.js, React, DB, or secret imports | `packages/client/` |
| Timesheet domain | Active/ownership/window/24-hour/write-budget rules and application operations | narrow port, clock, write budget | Server Actions, v1 services, compatibility route | No cookies, headers, provider clients, or global persistence lookup | `lib/domain/timesheets.ts`, `lib/domain/timesheets-port.ts` |
| Timesheet composition | Selects the active provider implementation and composes domain dependencies | backend selector, adapters, date/budget services | actions and v1 services | Native/Supabase implementations must satisfy the same port | `lib/db/timesheets.ts` |
| v1 contract mapping | Converts server rows/actors to released wire DTOs | app types, persistence actor, shared contracts | v1 routes and mobile/browser consumers | Server mapping is not a second public contract | `lib/api/v1/contracts.ts` |
| Shared persistence contracts | `Actor`, result/input types, and reusable actor guards; no aggregate repository interface | app/domain types | actions, API/services, ports and adapters | Keep provider-neutral and free of backend selection | `lib/db/types.ts` |
| Domain composition | Selects each active provider adapter and composes domain dependencies | backend selector, narrow ports, provider adapters | actions, API/services/domain | Do not recreate a global dispatcher; preserve both providers while supported | `lib/db/*.ts` composition modules |
| Native persistence | Domain-specific adapters plus `query`/`getPool` | `pg`, native migrations | domain composition modules | Parameterized SQL; explicit auth/scope checks; transaction/lock ordering matters | `lib/db/native/`, `lib/db/pool.ts` |
| Supabase persistence | Domain-specific adapters | Supabase client/PostgREST/RPC, RLS | domain composition modules | Preserve RLS and grants; scoped read RPCs stay `SECURITY INVOKER` | `lib/db/supabase/`, `lib/supabase/` |
| Portable retry compatibility | Resolves imported/local idempotency history, mapping, translation, replay authorization, and fresh-key admission | provider runtime, idempotency effects/ledger | `withIdempotency` | Fail closed on ambiguity, uncertainty, stale keys, and mapping errors; do not import operator tooling | `lib/idempotency/portable-retry.ts`, `lib/idempotency.ts` |
| Migration operator package | Offline export/plan/apply/verify/publish/recovery CLI and provider adapters | Node, PostgreSQL, Supabase admin APIs | operators and dedicated migration CI | Private workspace; application code must not import it; preserve migration/provenance recovery obligations | `tools/migration/src/`, `tools/migration/tests/` |
| Schema/migrations | Additive schema evolution and bootstrap | PostgreSQL / Supabase | persistence adapters, deployment | Do not rewrite applied migrations; cross-backend changes usually need both tracks | `db/migrations/`, `supabase/migrations/`, `db/migrate-runner.mjs` |
| Mobile client | Session/provider, API client, screens, secure storage, offline queue/sync | `/api/v1`, platform storage | end users/admin flows | Server remains authoritative; refresh tokens use secure storage boundary | `mobile/App.tsx`, `mobile/src/` |
| Deployment/runtime | Vercel/Supabase and native standalone/container deployment | Next build, environment, PostgreSQL/Supabase | operations | Backend selector is build-time; secrets remain server-side | `next.config.ts`, `Dockerfile`, `docker-compose.yml`, `deploy/`, `vercel.json` |
